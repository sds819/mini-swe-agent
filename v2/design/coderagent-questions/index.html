    Coding Agent 提问文档

    这份文档只提问，不回答。答案见 coderagent-answers.md。

    提问的出发点：一个 coding agent 要能被用起来，靠的不是「模型够聪明」，而是六件很具体的事—— 上下文放得下、工具管得住、任务调得动、状态存得回、效果量得准、出错救得回来。 下面的 33 个问题就是照这六件事问 coder agent 的，每一问都能在代码里找到答案。

    a. 上下文是如何管理的

    a1. 一次请求发给模型的消息由哪几部分组成？顺序是什么？每部分是什么角色（system / user / assistant）？ a2. 上下文预算怎么算？窗口大小从哪来（配置还是模型名）？token 数是怎么估的，估得准吗？ a3. 什么情况下触发压缩？压缩的切点怎么选？为什么切在「轮」而不是「消息」上？ a4. 被切掉的内容去哪了？摘要的 schema 是什么？摘要失败（模型不听话、解析不了）怎么办？ a5. 指令文件（AGENTS.md / CLAUDE.md）从哪儿加载？优先级是什么？子目录里的指令什么时候进来？ a6. 运行时状态（当前权限模式、todo 列表、压缩出来的摘要）是怎么进到上下文里的？会话中途权限模式变了怎么办？

    b. 工具如何管理

    b1. 内置工具有哪些？哪些可以启用、哪些可以禁用？外部（MCP、插件、子 agent 提供的）工具怎么进来？ b2. 工具的 schema 占多少上下文预算？超了预算时按什么顺序裁剪？哪些工具永远不会被裁掉？ b3. 模型一轮返回多个 tool call 时，是并行跑还是串行跑？什么情况下必须串行？结果顺序怎么保证？ b4. 一个工具执行失败（抛异常、参数不是合法 JSON）会怎样？会中断整轮吗？模型能看见什么？ b5. 有哪几种权限模式？每种模式下各类工具的默认判定是什么？ b6. 权限规则文件在哪里？项目规则和用户规则谁说了算？规则的匹配语义是什么（glob？正则？工具名？） b7. bash 这种能表达任何意图的命令怎么管？它是怎么被切分和判定的？ b8. edit / multi_edit 这类最关键的写文件工具，语义上有什么硬性保证？

    c. 任务如何调度

    c1. 一轮用户输入（turn）在代码里的主循环长什么样？哪些步骤是每轮都做的？ c2. 一轮会以哪些原因结束？每个停止原因分别代表什么？ c3. 跑得太久、too many turns、花钱太多，是怎么被卡住的？这些上限在哪配？ c4. 一轮进行中怎么被打断（用户在界面上按了 Esc，或者跑评测时要限时）？ c5. 子 agent 是怎么被调度的？它和主 agent 是什么关系——共享上下文吗？共享预算吗？它的话算谁的？ c6. 同一个会话里，模型可以中途换吗？换模型的依据是什么？ c7. 任务是 agent 自己拆解的，还是外部给的？那个 todo 列表存在哪儿、怎么回到上下文里？

    d. memory 和 state 如何管理

    d1. 「state」在这个项目里具体指什么？有哪几种状态？ d2. 事件日志是什么？存在哪儿、什么格式、为什么说它是「唯一事实来源」？ d3. 关掉程序再打开，前面的会话能接着聊吗？这是怎么做到的？ d4. 检查点（checkpoint）存的是什么？什么时候自动产生？能回退到什么粒度？ d5. 「memory」有几层？哪些是读进去的、哪些是写出来的？谁有权写用户级的 memory？ d6. 用户级数据（会话、检查点、规则、子 agent、插件信任表……）散落在哪些路径？评测怎么把它们全部隔离出去？

    e. 如何做评测与如何观察

    e1. 有没有跑一批任务并自动判分的入口？任务长什么样（怎么写一个）？ e2. 评测怎么保证「agent 的失败」和「harness 自己的失败」分得开？隔离是怎么做的？ e3. 报告里有什么？fingerprint 是什么、为什么需要它？ e4. 两次运行怎么比？「这次改动让 agent 变差了」这种结论是怎么得出来的？ e5. 一次真实会话怎么观察？指标是从哪儿算出来的？能不能导出成别的系统能吃的格式？ e6. CI 里跑的是什么？哪些检查是每次 PR 都跑的、哪些要手动？

    f. 如何做约束以及恢复

    f1. 约束一共有几层？权限、规则、hook、deny_paths、include_dirs、沙箱，各自管的是什么？ f2. hook 有哪几个触发点？hook 自己挂了（超时、崩了、输出不合法）会挡住操作吗？ f3. hook 想改写参数 / 改写用户提问，这两件事怎么区分？ f4. 出错之后能恢复吗？回退对话、回退文件、恢复旧会话、分叉一个新会话，分别怎么操作？各自能恢复什么、不能恢复什么？ f5. 模型调用失败、上下文溢出、工具失败——这三种失败分别怎么处理？ f6. 沙箱管住的是什么、管不住的是什么？边界到底在哪？

    这份文档怎么用

    1. 答案文档按 a1 … f6 的编号一一对应，每条答案都指向具体文件与函数。
    2. 答案里出现的「设计意图」和「当前实现的取舍」分开写——取舍是可以变的，意图是承重的。
    3. 想验证某条答案，直接去 src/coderagent/ 搜那个函数名；单测在 tests/coderagent/ 下按模块分目录。
