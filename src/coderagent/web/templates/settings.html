Model

The settings are written to the user level configuration file (~/.coderagent/config.yaml). The project level file is never written. A new session picks the new settings up; the running session keeps the model it has.

Example: a third party endpoint

The model name can be an alias of the model list of a litellm config file. The key of the endpoint then stays in that file, not here. 

# ~/.coderagent/litellm_config.yaml
model_list:
  - model_name: nengpa/minimax-m2.7
    litellm_params:
      model: openai/MiniMax-M2.7
      api_base: https://api.nengpa.com/v1
      api_key: sk-cp-...

The model is the model litellm calls, with the provider in front of it. The api_base stops at /v1: litellm appends /chat/completions to it. 

# ~/.coderagent/config.yaml
model:
  model_name: nengpa/minimax-m2.7
  litellm_config: ~/.coderagent/litellm_config.yaml

Permissions

The permissions go to the same user level configuration file. A new session picks the mode up; the running session keeps the mode it has. The mode of a running session is in the chat page.
